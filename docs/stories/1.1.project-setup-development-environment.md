# Story 1.1: Project Setup & Development Environment

## Status
Draft

## Story
**As a** developer,
**I want** a complete backend development environment with hot-reload, testing, and code generation capabilities,
**so that** I can efficiently build and test ERP backend functionality with consistent tooling.

## Acceptance Criteria
1. Go project initialized with proper module structure following existing `/project/<module>` pattern
2. Docker Compose development environment including PostgreSQL, NATS JetStream, and Redis containers
3. Makefile commands for `make dev`, `make test`, `make build`
4. Hot-reload functionality for Go backend during development
5. Code generation pipeline established for GORM models and OpenAPI specs
6. Git hooks configured for pre-commit linting, formatting, and basic test execution

## Dev Notes

### Previous Story Insights
This is the first story in the project, establishing the foundation for all future development.

### Technology Stack Requirements
[Source: docs/architecture/tech-stack.md]
- **Go**: 1.21+ for backend development
- **PostgreSQL**: 14+ as primary database
- **NATS JetStream**: v2.10+ for event-driven messaging
- **Redis**: 7.0+ for caching and session storage
- **Docker**: 24+ for containerization
- **Echo**: v4.11+ HTTP API framework
- **Huma**: v2.0+ for OpenAPI-first development

### Project Structure Requirements
[Source: docs/architecture/source-tree.md]
The project follows a modular monolith architecture:
```
erp-project/
└── erp/                    # Go Backend (Modular Monolith)
    ├── cmd/all/main.go     # Main application entry point
    ├── project/            # Business domain modules
    ├── pkg/                # Shared packages
    ├── gen/                # Generated code (DO NOT EDIT)
    ├── configs/            # Configuration files
    └── Makefile            # Build and development tasks
```

### Database and Infrastructure
[Source: docs/architecture/database-schema.md, docs/architecture/infrastructure-and-deployment.md]
- PostgreSQL with UUID primary keys and soft deletes
- NATS JetStream for event streaming between modules
- Redis for session management and caching
- Docker Compose for development environment
- Multi-stage Docker builds for production optimization

### Code Generation Requirements
[Source: docs/architecture/coding-standards.md]
- **Critical Rule**: Never manually edit files in `gen/db/` - always regenerate with `make models`
- GORM Gen for type-safe database queries
- Generated models location: `gen/db/model/`
- Generated queries location: `gen/db/query/`

### Testing Requirements
[Source: docs/architecture/test-strategy-and-standards.md]
- **Framework**: Go native testing with Testify v1.8+
- **File Convention**: `*_test.go` files alongside source code
- **Coverage Goals**: Minimum 80% for unit tests, 70% for integration tests
- **Test Infrastructure**: Testcontainers for realistic database testing
- **Mocking**: Use Testify/mock and GoMock for interface mocking

### File Locations for New Code
Based on existing project structure:
- Enhanced Makefile: `/Makefile` (existing, needs updates)
- Docker Compose: `/docker-compose.yaml` (existing, needs NATS/Redis)
- Git hooks: `.git/hooks/` directory
- Generated OpenAPI specs: `/gen/openapi/` (to be created)
- Integration tests: `/tests/integration/` (to be created)

### Technical Constraints
- Go version must be 1.21+ (currently using 1.23)
- All database access must use repository pattern with generated GORM models
- Module registration required in `cmd/all/main.go` for new modules
- Hot-reload must work for Go backend during development
- All API endpoints must use Huma v2 for OpenAPI generation
